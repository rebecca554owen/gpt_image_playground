# 4K 尺寸与模型选择冲突审计

## 总体结论

当前流程存在 P1 级产品逻辑冲突：同一个“是否使用 4K”的决定同时出现在设置页模型选择和生成页尺寸选择中，但两处状态彼此独立。客户可能保持 2K 模型，却在尺寸弹窗选择 4K；界面不会阻止，也没有解释最终会使用哪个模型或如何计费。

推荐把尺寸弹窗设为唯一的客户选择入口，模型由后台自动映射。客户只需要理解输出规格、尺寸和费用，不需要理解模型 ID。

## 审计步骤

### 1. 设置页选择模型 — 健康度：差

证据：`01-model-setting.jpg`

- 设置页提供 2K 与 4K 两个模型选择，并把模型 ID、推荐和 10× 费用暴露给客户。
- 这一步已经决定了请求模型，但生成页仍允许再次选择 1K、2K 或 4K。
- 模型 ID 是实现细节，不应该成为普通客户完成出图的前置知识。

### 2. 尺寸弹窗选择 4K — 健康度：差

证据：`02-size-4k.jpg`

- 客户可直接选择 4K 和 16:9，并看到将使用 `3840x2160`。
- 该弹窗没有说明会切换到 4K 专用模型，也没有显示 10× 费用。
- 选择状态主要依赖颜色，按钮没有形成清晰的单选组语义，键盘和读屏体验需要补充验证。

### 3. 确认尺寸 — 健康度：差

- 确认区只展示像素尺寸，没有展示输出档位、费用倍率和最终模型类别。
- 用户会把“确定”理解为只确认尺寸，无法预期它还会影响模型和费用。

## 最高优先级问题

### [P1] 4K 存在两个独立的选择入口

设置页选择模型，尺寸弹窗选择分辨率，两者都在表达“是否使用 4K”，却没有单一真相来源。

### [P1] 10× 费用没有出现在最终决策点

费用提示只在设置页出现。客户在尺寸弹窗点击 4K 时看不到价格差异，容易产生费用争议。

### [P1] 后台模型概念暴露给普通客户

客户真正关心的是清晰度、尺寸、适用场景和费用。要求客户理解 `gpt-image-2` 与 `gpt-image-2-4k` 会增加认知负担。

### [P2] 自动尺寸和自定义宽高的模型规则不明确

当前界面没有说明自动尺寸使用哪个模型，也没有说明自定义尺寸超过标准档位时是否会自动升级到 4K。

## 推荐方案：尺寸弹窗成为唯一入口

保留现有 1K、2K、4K 三个按钮，但把模型选择从客户设置页移除或改成只读的管理员映射。

| 客户选择 | 后台模型 | 费用提示 |
|---|---|---|
| 1K | `gpt-image-2` | 1× 基础费用 |
| 2K | `gpt-image-2` | 1× 基础费用 |
| 4K | `gpt-image-2-4k` | 10× 费用 |

### 尺寸弹窗建议

- 将“基准分辨率”改为“输出清晰度”。
- 1K、2K 按钮增加“1×”小标签。
- 4K 按钮增加醒目的“10× 费用”标签。
- 选择 4K 后，在确认区显示：`3840×2160 · 4K 超清 · 10× 费用`。
- 4K 状态下，主按钮改为：`确认使用 4K（10×费用）`。
- 如果一次生成多张，提示：`本次生成 N 张，每张按 10× 计费`。

### 设置页建议

- 普通客户不再选择模型。
- 如果必须保留自定义 API 能力，放入“高级设置 > 模型映射”，显示两项配置：
  - 标准 1K/2K 模型
  - 4K 专用模型
- 客户生成图片时不切换全局模型，系统根据本次任务的输出档位选择模型。

### 自动与自定义尺寸

- 自动尺寸默认使用标准模型，不会静默产生 4K 的 10× 费用。
- 自定义尺寸超过标准模型能力时，自动切换为 4K，并在确认前显示明确的 10× 提示。
- 具体升级边界应由后端能力约束决定，不能只根据界面文案猜测。

## 实现约束

- 不建议在客户点击 4K 后直接修改全局 `activeProfile.model`，否则会影响后续任务或其他页面状态。
- 建议给任务参数保留明确的输出档位，例如 `resolutionTier: '1K' | '2K' | '4K'`。
- 提交请求时按本次任务档位派生模型：4K 使用 `gpt-image-2-4k`，其他使用 `gpt-image-2`。
- 自定义尺寸需要独立的档位判定规则，并在 UI 中展示判定结果。

## 证据限制

- 本次可以确认前端存在双入口和费用提示缺位。
- 无法仅从界面确认两个模型的精确尺寸边界、失败行为和实际计费接口；实现前需要以后端模型契约为准。
